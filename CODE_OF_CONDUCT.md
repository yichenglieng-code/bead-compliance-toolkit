# Code of conduct

## The short version

Be straightforward and civil. Assume the person on the other end is trying to get
broadband to somewhere that does not have it.

## What that means here

**Expected:**

- Disagree with the work, technically and directly. "This threshold is wrong, here is
  the citation" is exactly the contribution this project wants.
- Assume competence. Someone asking a basic question about BEAD reporting may be an
  expert network engineer new to the compliance side, or the reverse.
- Accept that the maintainer will say no to things, and that "no" usually means scope
  rather than merit.

**Not expected:**

- Harassment, insults, or personal attacks
- Discriminatory language or imagery of any kind
- Publishing private information without permission
- Persistent unwelcome contact after being asked to stop
- Deliberately wasting people's time: bad-faith argument, spam, low-effort automated
  pull requests

Being right about a technical point does not license being unpleasant about it.

## A domain-specific one

**Never post real subscriber or location data**, in an issue, a pull request, a test
fixture, or an example. Use synthetic values in the style already in `examples/`.

This is in the code of conduct rather than only in the contributing guide because it
is about other people's privacy, not about code quality. Content containing real
subscriber data will be removed without waiting for discussion.

## Scope

Applies in this repository's issues, pull requests, discussions, and commit messages,
and to anyone representing the project elsewhere.

## Reporting

Report to the maintainer, [@yichenglieng-code](https://github.com/yichenglieng-code),
by opening a private security advisory on this repository if the matter is sensitive,
or by direct message.

Given that this is a one-maintainer project, the process is not elaborate: the report
is read, it is handled, and the reporter is told what happened. Realistically that
means removing content, or blocking someone, or explaining why not.

The obvious limit: if a complaint is about the maintainer, there is nobody else here
to escalate to. In that case say so publicly in an issue, or fork the project. The
licence permits it and [GOVERNANCE.md](GOVERNANCE.md) explains how. That is a thin
remedy, and naming it is better than implying a neutral process exists when it does
not.
